# 多 Agent 并行调度执行计划

本文档基于 `specs/tasks.md` 与 `specs/plan.md` 生成，用于指导多个虚拟子 Agent 按依赖关系并行执行任务。

## 1. 调度目标

目标是在不破坏 TDD 顺序、不跨越依赖边界、不共享同一可变文件的前提下，最大化并行效率。

调度原则：

- 先执行无业务实现的工程骨架任务。
- Phase 2、Phase 3、Phase 4 必须严格测试先行。
- `[P]` 任务优先并行分配给不同子 Agent。
- 未标记 `[P]` 的任务按依赖链串行或小批量并行。
- 同一个文件同一时间只交给一个子 Agent 修改。
- 每个子 Agent 完成任务后必须运行与任务相关的最小验证。
- 每个阶段完成后由集成协调 Agent 执行阶段级检查。

## 11. 风险与协调策略

### 11.1 易冲突文件

以下文件容易被多个任务修改，必须由集成协调 Agent 串行处理：

- `frontend/src/router/index.ts`
- `backend/src/main/resources/application.yml`
- `docker-compose.yml`
- `backend/src/main/java/com/cooperation/infrastructure/security/SecurityConfig.java`
- `backend/src/main/resources/db/migration/V1__init_schema.sql`

### 11.2 TDD 检查点

必须设置以下阻断点：

- D001-D013 未完成时，不启动 D014-D036。
- A001-A019 未完成时，不启动 A020-A043。
- W001-W011 未完成时，不启动 W012-W033。

### 11.3 阶段验收命令建议

后端阶段：

```text
mvn test
```

前端阶段：

```text
npm run test:unit
npm run build
```

端到端阶段：

```text
npm run test:e2e
```

### 11.4 集成规则

- 每个子 Agent 完成任务后，只提交对应目标文件。
- 同一波次结束后，集成协调 Agent 统一检查任务依赖是否满足。
- 每个阶段结束后，运行阶段级测试。
- 全部阶段结束后，运行后端测试、前端测试和 E2E。
